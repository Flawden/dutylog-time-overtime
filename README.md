# Журнал смен

Календарь смен с Markdown-заметками. Spring Boot (бэкенд + раздача статики) + веб-интерфейс на чистом JS. Данные — в файловой базе H2, живут между перезапусками.

## Быстрый старт

Нужны: **JDK 17+** и **Maven** (или просто IntelliJ IDEA — она всё сделает сама).

**Через IDEA (проще всего):**
1. File → Open → выбери папку проекта (где `pom.xml`).
2. Дождись, пока IDEA скачает зависимости.
3. Запусти класс `ShiftsApplication` (зелёная стрелка).
4. Открой http://localhost:8080

**Через консоль:**
```bash
mvn spring-boot:run
```

База создастся сама в `./data/shifts.mv.db`. Удалишь файл — начнёшь с чистого листа.

> ⚠️ **Если запускал версию без авторизации** — удали папку `./data` перед первым запуском этой версии. Схема БД изменилась (у смен и дней появился владелец), и `ddl-auto=update` не сможет корректно домигрировать старые данные без владельца.

## Авторизация

При первом открытии попадёшь на `/login.html` — там вход и регистрация. Каждый пользователь видит только свои смены, свои дни и свои заметки. Стартовый набор смен выдаётся при регистрации.

Как это устроено (важно понимать, спрашивают на собеседованиях):
- **Сессии, не токены.** После входа Spring Security кладёт в браузер cookie `JSESSIONID`, и браузер сам шлёт её с каждым запросом. Для классического веб-приложения это проще и безопаснее самодельного JWT.
- **Пароли — BCrypt-хэши.** В базе пароля в открытом виде нет. Посмотри в h2-console на таблицу `USERS` — увидишь.
- **Проверка владельца — в каждом контроллере.** Обрати внимание на `.filter(st -> st.getOwner().getId().equals(...))` — без этой строки любой пользователь мог бы удалять чужие смены, зная id. Это классическая уязвимость (IDOR), её наличие проверяют на пентестах.
- **CSRF отключён** в `SecurityConfig` — сознательное упрощение для локального проекта, чтобы fetch-запросы работали без прокидывания токена. Перед выкладкой в интернет включи обратно (убери `.csrf(csrf -> csrf.disable())`) и добавь передачу токена в заголовке — это отдельный вечер и хорошее упражнение.

Консоль БД (посмотреть таблицы руками): http://localhost:8080/h2-console, JDBC URL: `jdbc:h2:file:./data/shifts`, логин `sa`, пароль пустой.

## API

Все эндпоинты (кроме регистрации) требуют залогиненной сессии и работают с данными текущего пользователя.

| Метод  | URL                          | Что делает |
|--------|------------------------------|------------|
| POST   | `/api/auth/register`         | регистрация: `{"username":"dan","password":"secret"}` |
| GET    | `/api/auth/me`               | имя текущего пользователя |
| POST   | `/perform_login`             | вход (form-data: username, password) — обрабатывает Spring Security |
| POST   | `/logout`                    | выход |
| GET    | `/api/shift-types`           | список типов смен |
| POST   | `/api/shift-types`           | создать: `{"name":"Сутки","hours":24,"color":"#E0653A"}` |
| DELETE | `/api/shift-types/{id}`      | удалить тип (у дней смена снимается) |
| GET    | `/api/days?year=2026&month=7`| записи месяца |
| PUT    | `/api/days/2026-07-02`       | upsert: `{"shiftTypeId":3,"note":"# md"}`; пустая запись удаляется (204) |

Проверить руками можно curl'ом или Postman'ом.

## Важно знать

- **Проект не компилировался перед передачей** — писался без доступа к Maven Central. Код стандартный, но при первом запуске возможны мелочи. Читай стектрейс снизу вверх: первая строка с `ru.daniil.shifts` — твоя.
- `ddl-auto=update` удобен для разработки, но в проде так не делают — там миграции (Flyway). Пункт в роадмапе.
- Заметки хранятся как `@Lob` (CLOB) — длина не ограничена.
- Фронтенд шлёт заметку на сервер с задержкой 600 мс после последнего ввода (debounce), чтобы не спамить запросами на каждый символ.

## Роадмап (в порядке приоритета)

1. **Запустить и потыкать.** Убедись, что смены ставятся, заметки сохраняются, месяц переключается. Проверь в h2-console, что данные реально в БД.
2. **Разобраться в коде.** Пройди путь одного запроса: клик по смене → `fetch` в index.html → `DayController.upsert` → репозиторий → БД. Это главный учебный эффект проекта.
3. **Валидация.** Добавь `spring-boot-starter-validation` и аннотации (`@NotBlank`, `@Size`) на DTO. Сейчас валидация ручная и минимальная.
4. **Обработка ошибок.** `@ControllerAdvice` + `@ExceptionHandler`, чтобы API возвращал внятный JSON с ошибкой, а не стектрейс.
5. **Тесты.** `@DataJpaTest` на репозитории, `@WebMvcTest` на контроллеры. На собеседованиях спрашивают.
6. **Миграции.** Замени `ddl-auto=update` на Flyway. Один вечер, а понимание — must-have для DevOps-трека.
7. **Экспорт для бухгалтерии.** Эндпоинт «часы за месяц» → CSV. Тут проект встречается с твоим трекером переработок.
8. **PWA.** Добавь manifest.json + service worker — и это ставится на Android как приложение с иконкой. Нативный Android не нужен, пока не упрёшься в его отсутствие.
9. **Доступ с телефона.** Пока сервер дома: Tailscale (ты его уже смотрел) — и телефон видит http://имя-машины:8080 из любой сети. Либо потом VPS.
10. ~~Авторизация~~ — **сделана** (Spring Security, сессии, BCrypt). Твоя задача — прочитать `SecurityConfig` и `AuthController` и понять каждую строчку. Перед выносом в интернет: включить CSRF обратно и добавить HTTPS (на VPS — nginx + certbot, за час гуглится).
