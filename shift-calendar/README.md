# Журнал смен

Календарь смен с Markdown-заметками. Spring Boot (бэкенд + раздача статики) + веб-интерфейс на чистом JS. Данные — в файловой базе H2, живут между перезапусками.

## Идея продукта

Пользователь открывает календарь и отмечает, какая смена была в конкретный день. В базовом наборе есть три встроенные смены: **«Дневная»**, **«Ночная»** и **«Выходной»**. Всё остальное пользователь создаёт сам: «5 часов», «12 часов», «Сутки», «Отпуск», «Больничный» и любые другие варианты. Для каждой кастомной смены задаются название, цвет и количество часов.

В каждый день можно провалиться и написать заметку в Markdown. Если в дне есть заметка, на клетке календаря появляется отметка. От выбранного дня можно запустить автозаполнение графика: 2/2, день/ночь/48, пятидневка 5/2 и простые варианты 1/3. По умолчанию график заполняется на 31 день вперёд, включая следующий месяц. Пятидневка привязана к реальным дням недели: Пн–Пт рабочие, Сб–Вс выходные. После заполнения каждый день всё равно редактируется вручную.

Добавлен простой учёт переработки и отгулов: в дне можно отдельно указать дополнительные часы, например ППР после смены, и отдельно часы, которые списаны как отгул. Баланс периода считается как `переработка - отгулы`. Например: в четверг обычная дневная смена + 15 часов ППР, в пятницу списан отгул по дневной смене 8 часов. Баланс: `15 - 8 = +7 часов`.

Дальше проект можно развивать в сторону уведомлений: Android/PWA push-уведомления, Telegram-бот, напоминания перед событиями, «будильник» перед сменой, более строгий табель план/факт и накопительный баланс переработок между месяцами.

## Что доработано в этой версии

- Исправлено автосохранение заметок: теперь сохраняется снимок текста, поэтому заметка не теряется при быстром переключении месяца.
- Стартовые встроенные смены: «Дневная», «Ночная» и «Выходной».
- Все остальные типы смен предполагаются пользовательскими: их нужно создавать вручную с названием, цветом и часами.
- Встроенные смены действительно `builtin=true` и не удаляются ни с фронта, ни через API.
- Добавлено автозаполнение графика от выбранного дня: 2/2, день/ночь/48, пятидневка 5/2, день/72, ночь/72. По умолчанию заполняется 31 день вперёд, поэтому можно проходить через границу месяца.
- Массовое заполнение меняет только тип смены и не стирает Markdown-заметки, переработки и отгулы в днях.
- Добавлен учёт переработки/отгулов в дне: дополнительные часы, списанные часы и баланс за месяц.
- В календаре появляется маленькая отметка `+7ч` или `-8ч`, если в дне есть начисление/списание переработки.
- Добавлена валидация типов смен: название, часы 0–24, цвет `#RRGGBB`.
- API начал возвращать понятные JSON-ошибки, которые фронтенд показывает в шапке.
- Добавлен базовый PWA-слой: `manifest.json`, service worker и иконки. На Android страницу можно добавить на главный экран как приложение.
- Добавлен `application-prod.properties`, где отключена H2-console для первого публичного запуска.

## Быстрый старт

Нужны: **JDK 17+** и **Maven** (или просто IntelliJ IDEA — она всё сделает сама).

**Через IDEA (проще всего):**
1. File → Open → выбери папку проекта (где `pom.xml`).
2. Дождись, пока IDEA скачает зависимости.
3. Запусти класс `ShiftsApplication` (зелёная стрелка).
4. Открой http://localhost:8080

**Через консоль:**
```bash
mvn spring-boot:run
```

База создастся сама в `./data/shifts.mv.db`. Удалишь файл — начнёшь с чистого листа.

> ⚠️ **Если запускал версию без авторизации** — удали папку `./data` перед первым запуском этой версии. Схема БД изменилась (у смен и дней появился владелец), и `ddl-auto=update` не сможет корректно домигрировать старые данные без владельца.

## Авторизация

При первом открытии попадёшь на `/login.html` — там вход и регистрация. Каждый пользователь видит только свои смены, свои дни и свои заметки. При регистрации выдаются три базовые смены: «Дневная», «Ночная» и «Выходной». Остальные варианты пользователь создаёт сам.

Как это устроено (важно понимать, спрашивают на собеседованиях):
- **Сессии, не токены.** После входа Spring Security кладёт в браузер cookie `JSESSIONID`, и браузер сам шлёт её с каждым запросом. Для классического веб-приложения это проще и безопаснее самодельного JWT.
- **Пароли — BCrypt-хэши.** В базе пароля в открытом виде нет. Посмотри в h2-console на таблицу `USERS` — увидишь.
- **Проверка владельца — в каждом контроллере.** Обрати внимание на `.filter(st -> st.getOwner().getId().equals(...))` — без этой строки любой пользователь мог бы удалять чужие смены, зная id. Это классическая уязвимость (IDOR), её наличие проверяют на пентестах.
- **CSRF отключён** в `SecurityConfig` — сознательное упрощение для локального проекта, чтобы fetch-запросы работали без прокидывания токена. Перед выкладкой в интернет включи обратно (убери `.csrf(csrf -> csrf.disable())`) и добавь передачу токена в заголовке — это отдельный вечер и хорошее упражнение.

Консоль БД (посмотреть таблицы руками): http://localhost:8080/h2-console, JDBC URL: `jdbc:h2:file:./data/shifts`, логин `sa`, пароль пустой.

## API

Все эндпоинты (кроме регистрации) требуют залогиненной сессии и работают с данными текущего пользователя.

| Метод  | URL                          | Что делает |
|--------|------------------------------|------------|
| POST   | `/api/auth/register`         | регистрация: `{"username":"dan","password":"secret"}` |
| GET    | `/api/auth/me`               | имя текущего пользователя |
| POST   | `/perform_login`             | вход (form-data: username, password) — обрабатывает Spring Security |
| POST   | `/logout`                    | выход |
| GET    | `/api/shift-types`           | список типов смен |
| POST   | `/api/shift-types`           | создать: `{"name":"Сутки","hours":24,"color":"#E0653A"}` |
| DELETE | `/api/shift-types/{id}`      | удалить пользовательский тип; «Дневная»/«Ночная»/«Выходной» вернут 409 |
| GET    | `/api/days?year=2026&month=7`| записи месяца |
| PUT    | `/api/days/2026-07-02`       | upsert: `{"shiftTypeId":3,"note":"# md","overtimeHours":15,"timeOffHours":8}`; пустая запись удаляется (204) |
| POST   | `/api/days/fill`             | заполнить график: `{"startDate":"2026-07-02","days":31,"shiftTypeIds":[1,2,3,3],"overwriteExistingShift":true}` |

Проверить руками можно curl'ом или Postman'ом.

## Важно знать

- **В этой среде проект не удалось собрать Maven-ом**, потому что здесь нет команды `mvn`. JS-файлы проверены на синтаксис через Node, а Java-код написан под стандартный Spring Boot 3.3.5. При первом запуске в IDEA/Maven смотри стектрейс снизу вверх: первая строка с `ru.daniil.shifts` — твоя.
- `ddl-auto=update` удобен для разработки, но в проде так не делают — там миграции (Flyway). Пункт в роадмапе.
- Заметки хранятся как `@Lob` (CLOB), а DTO ограничивает ввод до 20 000 символов, чтобы случайно не забить базу огромным текстом.
- Фронтенд шлёт заметку на сервер с задержкой 600 мс после последнего ввода (debounce), чтобы не спамить запросами на каждый символ. Перед переключением месяца и перед автозаполнением ожидающее сохранение принудительно отправляется.
- Автозаполнение графика работает через `/api/days/fill`: сервер меняет смену, но сохраняет заметки, переработки и отгулы. Это важно, чтобы массовая расстановка не сносила дневниковые записи и баланс часов.
- Для обычных циклических графиков выбранный день считается первым днём шаблона. Для пятидневки используется привязка к неделе: Пн–Пт рабочие, Сб–Вс выходные, поэтому можно начать заполнение со среды и не ломать выходные.
