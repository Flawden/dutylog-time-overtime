# DutyLog i18n / Language switch

Status: v26.4.

DutyLog supports two interface languages:

- `ru` — Russian;
- `en` — English.

## Storage

Language is a user preference, not a role and not an account tier.

Database field:

```sql
users.language_preference VARCHAR(10) NOT NULL DEFAULT 'ru'
```

Migration:

```text
V19__user_language_preference.sql
```

The browser also stores a local fallback:

```text
dutylog.language.v1
```

This lets the login page and PWA shell keep the selected language before `/api/profile` is loaded.

## API

`GET /api/profile` returns:

```json
{
  "languagePreference": "ru"
}
```

`PUT /api/profile` accepts:

```json
{
  "languagePreference": "en"
}
```

Allowed values are only `ru` and `en`.

## Frontend design

The frontend uses a safe application dictionary. Users do not provide CSS, JavaScript, HTML or translation files. The i18n layer translates:

- static visible text;
- common dynamic UI labels;
- counters, page ranges and status chips;
- offline-sync diagnostics and warning copy;
- placeholders;
- titles and aria labels;
- calendar month and weekday names.

Business data entered by users is not intentionally translated.

## Scope notes

The language preference affects the web/PWA interface. Telegram command output can be localized later as a separate feature because bot text has a different UX and command vocabulary.
