# Product copy guide

Этот документ фиксирует стиль пользовательских текстов DutyLog.

## Принцип

Интерфейс должен говорить как продукт для пользователя, а не как заметки разработчика.

Хорошо:

```text
Сервер рассчитывает напоминания для браузера, Telegram и мобильных клиентов.
```

Плохо:

```text
Backend уже считает напоминания для веба, Android и будущего Telegram-бота.
```

## Тон

- Спокойный и уверенный.
- Без внутренних пометок `пока`, `будущий VPS`, `сделаем потом`.
- Без обращения `ты` в системных настройках.
- В подсказках использовать нейтральное обращение: `Выберите`, `Создайте`, `Откройте`.
- Короткие кнопки лучше длинных инструкций.

## Термины

| Внутренний термин | Пользовательский термин |
| --- | --- |
| backend | сервер |
| frontend | интерфейс |
| service worker | кэш приложения |
| CSRF | защита сессии |
| mobile sessions | мобильные сессии / активные устройства |
| FIFO | автоматическое списание старых остатков |
| custom shift | пользовательская смена |

## Диагностика

В разделе диагностики технические термины допустимы, но рядом должен быть понятный смысл. Например:

```text
Кэш приложения: активен
Защита сессии: работает
Сервер: 22.2
База данных: доступна
```

## Сообщения об ошибках

Сообщение должно объяснять, что сделать дальше:

Хорошо:

```text
У смены не указано время окончания. Откройте настройки смены и задайте время.
```

Плохо:

```text
Shift end missing.
```


## Диагностика — не пользовательская настройка

Служебные данные не должны висеть рядом с личным профилем, сменами и уведомлениями. Для них используется отдельный раздел `Система`, доступный администратору. В пользовательских настройках остаётся только то, что влияет на повседневную работу пользователя.
