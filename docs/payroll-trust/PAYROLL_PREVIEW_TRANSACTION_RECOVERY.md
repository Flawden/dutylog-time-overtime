# Восстановление загрузки Payroll при неполной настройке оплаты

Основание: отчёт DUTYLOG_DIAG_RESULT_20261006_031958 и журнал staging.
GET /api/v1/payroll/periods/2026-10 возвращал HTTP 500 с
UnexpectedRollbackException; список правил оплаты был пустым.

## Причина и исправление

PayrollOrdinaryPremiumPreviewService преобразует ожидаемые проблемы
настройки в blocked preview. До исправления вложенные Spring-сервисы
помечали общую транзакцию rollback-only, прежде чем адаптер перехватывал
ApiException. Поэтому ошибка проявлялась на commit корневого GET запроса.

Введён отдельный тип PayrollPricingUnavailableException для уже существующих
ожидаемых конфликтов настройки: отсутствуют правила или историческая ставка,
неполная/нулевая норма оклада, несовместимые валюты обычных доплат.
Три чистых сервиса чтения — PayPricingPolicyService,
HistoricalCompensationRateService и OrdinaryWorkPremiumPricingService —
не помечают участвующую транзакцию rollback-only именно для этого типа.
Существующие HTTP-коды, тексты и машинные коды конфликтов сохранены.

GET возвращает HTTP 200 с явным blocked preview и canCalculate=false.
Это не разрешает расчёт без оснований. Строгие вызывающие сервисы по-прежнему
получают исключение; выход исключения из корневой записывающей транзакции
откатывает её. Неожиданные ошибки продолжают помечать общую транзакцию
для отката. Общий запрет rollback для ApiException не добавлялся.

## Проверка

PayrollPreviewTransactionTest использует реальные источники смен и Actual Work,
настоящие Spring-сервисы и HTTP-контроллер без внешней тестовой транзакции.
Это позволяет проверить завершение транзакции самого запроса.

До исправления три HTTP сценария давали HTTP 500 и UnexpectedRollbackException.
После исправления они возвращают HTTP 200 с прежними причинами блокировки:
отсутствующие правила, отсутствующая историческая ставка и неполный график
оклада. Повторный GET также проходит. Дополнительно проверены откат записей
строгого вызывающего сервиса и rollback-only после перехваченной неожиданной
ошибки программирования.

Тесты UI, схемы OpenAPI и миграции базы в этом исправлении не изменены.
Мобильная вёрстка и полная диагностика задержек остаются следующими задачами.

## Замеры исходного сбоя

Два запросa месяца: клиент 1384/1697 мс, серверный журнал 609/931 мс.
Разница включает передачу по сети и накладные расходы клиента; она не
доказывает причину задержек отрисовки или перегрузку сервера.

После staging-деплоя повторить исходный диагностический пакет за октябрь.
Ожидаемый результат: HTTP 200 для обоих запросов месяца и явная причина
недостающей настройки, если пользователь ещё не заполнил её.
