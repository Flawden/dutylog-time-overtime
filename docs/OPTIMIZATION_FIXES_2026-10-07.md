# Оптимизация DutyLog: пакет OPTIMIZE

База: `b5bc4523cf46988b93314c30f430d1bd82363465`, ветка `test`.

## Изменения

- IndexedDB разделена по неизменяемому userId авторизованного пользователя. Снимки,
  очередь и ошибки содержат владельца. Выйти из аккаунта означает отключить его
  локальную идентичность, а не удалить несинхронизированные операции.
- Сервер сравнивает необязательный `X-DutyLog-Offline-Owner` с userId текущего Principal (повторно созданный логин не наследует старый кэш).
  При несовпадении возвращает 401 до контроллера. Это защищает отправку очереди
  от смены cookie в другой вкладке, включая гонку после предварительной проверки.
- Другая вкладка при смене аккаунта прекращает работу со старым локальным хранилищем.
  Web Locks защищает синхронизацию между вкладками; для старых браузеров остаётся
  прежняя блокировка с TTL в localStorage.
- Пустая очередь не запрашивает месяц и не публикует событие обновления данных.
  После фактически применённых изменений обновление сохраняется, включая частично
  обработанную очередь.
- 401 имеет типизированные status/url/method; offline fallback после 401 отключён.
- Параллельные ensureLoaded календаря одного store/даты используют один Promise.
  Явный refresh после изменения остаётся свежим запросом. Устаревший GET отменяется;
  sequence guard остаётся на случай ответа транспорта, игнорирующего отмену.
- Необязательный time/context календаря ограничен 1500 мс. Для Today сохранено ожидание авторитетной рабочей даты, чтобы таймаут не подменял часовой пояс. Отмена не распространяется на
  денежные операции или другие записи. Автоматических повторов POST нет.
- Сессии, интеграции, история зон и редакторы настроек загружаются при входе
  в настройки. Редактор типов смен остаётся доступен из календаря.
- Startup productivity загружает выбранный день; полные board/inbox/important
  списки загружаются для соответствующего маршрута. Публичный refreshAll без
  маршрута сохраняет полное обновление для существующих mutation callers.
- Нормы времени в двух расчётных путях читаются одним диапазонным запросом.
  LOCAL_OVERRIDE имеет приоритет над BASE, включая явное NONE и нулевую норму.
- Разбиение каждого actual-work interval по датам выполняется один раз на запрос.
  Наличие явного фактического интервала и правила перерывов/DST не меняются.
- CalendarRange использует одну полную FIFO-проекцию и один список флагов модулей
  для собственного summary/account. История FIFO не обрезается по месяцу.
- Vue собирается как приложение, а не ES-библиотека: включена обычная минификация.
  Постоянный entry остаётся небольшим; основной код имеет хэшированные URL.
- 13 нижних legacy-скриптов получили defer с сохранением порядка. Ранний скрипт
  темы остаётся синхронным, чтобы не появлялась вспышка неправильной темы.
- Bundle audit учитывает legacy JS отдельно. Существующие лимиты Vue не повышены.

## Данные старой версии

Общий `dutylog-offline` не удаляется и не присваивается пользователю автоматически.
У его записей отсутствует достоверный владелец. Новый код его не читает и не
отправляет. Если до обновления были несинхронизированные операции в старой версии,
их нужно разбирать отдельно; сохранение исходной базы позволяет восстановление.
Новый персональный снимок создаётся после успешного чтения сервера.

## Проверки и границы доказательства

Локально: TypeScript, 94 Vitest, 6 Node regression tests, release-check, сборка и
bundle audit. В архиве есть точные журналы и отдельный статус Java-проверки.
Написаны два дополнительных Playwright сценария (всего 61): смена аккаунта с
очередью и отсутствие eager settings/пустого обновления месяца.
Java baseline: 2912 выполняемых тестов, 392 класса; исходных @Test методов 2799.
Полный clean verify, coverage и browser E2E являются обязательными воротами
Termux/CI. Статус написанного теста не равен статусу выполненного теста.

Измерение файлов: примерно 980 КБ → 664 КБ raw и 244 КБ → 211 КБ gzip для Vue.
Это не измерение скорости сети или CPU телефона. Новые first/warm-launch timings
можно оценить только после успешной выкладки.

## Что аудит ещё не закрывает

- Полное устранение двойного legacy/Vue calendar ownership и общая metadata-cache.
- Разблокирование всего интерфейса по локальному снимку до сетевого обновления:
  сначала нужен единый owner loader, merge очереди и проверка timezone/range.
- GET fast path для default presets: owner lock и повторная проверка first-run
  сохранены. Их нельзя удалять без проверки конкурентного seed на PostgreSQL.
- Удаление retired legacy-кода и повторных внутренних чтений FIFO reconciliation.
  Согласованность allocations и frozen payroll revisions имеет приоритет.

Этот пакет закрывает опасные ошибки и сокращает основную лишнюю работу; он не
выдаётся за полное закрытие всех 13 пунктов аудита.
