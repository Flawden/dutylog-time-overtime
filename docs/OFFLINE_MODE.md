# Offline Mode / local-first lite

DutyLog остаётся серверным приложением: backend и PostgreSQL являются главным источником истины. Offline Mode добавляет локальную выживаемость в браузере, чтобы календарь и базовые записи были доступны без связи.

## Что доступно без сети

- Просмотр последнего локального снимка календаря.
- Просмотр заметок, задач, важных отметок и баланса на момент последней синхронизации.
- Изменение смены выбранного дня.
- Редактирование заметки выбранного дня.
- Установка состояния задачи: выполнена / не выполнена.

## Что требует связи с сервером

- Начисление переработки.
- Списание отгула.
- Управление типами смен.
- Быстрые сценарии.
- Уведомления.
- Telegram-интеграция.
- Профиль и пароль.
- Важные даты.

Эти операции не выполняются оффлайн, потому что часть из них использует серверную бизнес-логику: FIFO, проверки пересечений, разбиение интервалов и безопасность аккаунта.

## Хранилище

В браузере создаётся IndexedDB-база `dutylog-offline` со store:

- `snapshot` — последний успешный снимок календаря;
- `queue` — очередь безопасных изменений;
- `meta` — служебные данные и операции, которые сервер не принял.

## Синхронизация

Очередь проигрывается строго по порядку. Если сеть пропала, синхронизация останавливается и продолжится позже. Если сервер вернул 400/404/409, операция переносится в список «не применилось», чтобы не терять данные молча.

Операции описывают целевое состояние, а не действие. Например, задача отправляется как `done: true`, а не как «переключить». Поэтому повторная отправка безопасна.

## Роль Service Worker

Service Worker отвечает только за оболочку приложения. Данные не кэшируются в Service Worker и не смешиваются с HTTP-кэшем. Все пользовательские данные offline-режима находятся в IndexedDB.

## Ручной тест

DevTools → Network → Offline:

1. Открыть приложение онлайн.
2. Дождаться загрузки календаря.
3. Выключить сеть.
4. Перезагрузить страницу.
5. Проверить, что календарь открылся из локальной копии.
6. Изменить заметку выбранного дня.
7. Поставить задачу выполненной или снова открыть её.
8. Проверить, что счётчик неотправленных изменений вырос.
9. Включить сеть.
10. Проверить, что очередь отправилась.
11. Перезагрузить страницу и проверить, что данные на сервере совпали.


## Панель синхронизации

Индикатор в шапке открывает панель синхронизации. В ней видно:

- какие операции ожидают отправки;
- какие операции сервер не применил;
- когда была последняя успешная синхронизация;
- предупреждение, если локальные данные старше суток.

Из панели можно запустить синхронизацию вручную, повторить все ошибки, повторить одну ошибочную операцию, удалить ошибочную операцию из списка или скачать локальное offline-состояние в JSON. Экспорт нужен как аварийная страховка: если в браузере остались важные оффлайн-заметки, их можно сохранить до ремонта синхронизации.

Emergency export содержит:

```json
{
  "exportedAt": "...",
  "app": "DutyLog",
  "version": "22.3",
  "snapshot": {},
  "queue": [],
  "failed": [],
  "meta": {}
}
```

## Защита от двух вкладок

Перед проигрыванием очереди вкладка берёт короткий lock в `localStorage`. Если другая вкладка уже синхронизирует очередь, повторный запуск не начинается. Lock автоматически протухает, поэтому зависшая вкладка не блокирует синхронизацию навсегда.

## Устаревшие данные

Если последний локальный снимок старше суток, индикатор помечает данные как устаревшие. Это не блокирует работу, но честно показывает, что календарь и баланс могут отличаться от сервера.


## Диагностика оффлайна

В v21.2 панель синхронизации показывает не только очередь, но и краткую диагностику текущего web/PWA-клиента:

- состояние online/offline;
- доступность IndexedDB;
- время последней синхронизации;
- возраст локального snapshot;
- количество операций в очереди;
- количество операций в списке «не применилось»;
- состояние `syncLock` для защиты от двух вкладок.

Кнопка `Скопировать диагностику` формирует безопасный текстовый отчёт. Он не содержит паролей, токенов Telegram, cookie или содержимого заметок. Отчёт нужен для разбора проблем оффлайн-синхронизации без доступа к серверной админке.

Текущий клиент приложения — web/PWA внутри Spring Boot-монолита. Отдельного native mobile-приложения в этом релизе нет, поэтому offline QA выполняется в браузере и в установленной PWA-оболочке.


## v22.3 offline scope

В production launch offline-логика не расширялась. v22.3 сохраняет scope v21.x: смена выбранного дня, заметка дня и целевое состояние задачи `done: true/false`.
