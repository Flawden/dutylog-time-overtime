# Мобильная вёрстка и диагностика задержек

База: 74ae181ab1ddd4b554445d3485f474b8beda8777.

До исправления реальный браузер (390×844, регистрация и onboarding приложения)
показал верх диалога на y=-2: max-height вычитал 16px, внешние отступы занимали
36px. Поля ручных операций имели высоту 23px. Два новых теста воспроизвели ошибки.

Высота диалога теперь учитывает отступы и safe-area. Весь диалог прокручивается,
поэтому действия доступны при коротком экране и увеличенном тексте. Заголовок
переносится, кнопка закрытия не сжимается, колонки footer используют minmax(0,1fr).
Поля и кнопки зарплаты имеют min-height 44px, padding, границы и focus-visible.
Описание синхронизации объясняет действия пользователя вместо внутренних деталей.
Финансовые формулы, API и схема БД не менялись.

При обычном открытии зарплаты браузер наблюдал один GET месяца, один GET правил
и один GET компонентов. Проверка защищает от дублирования первых двух запросов.
Локальные H2/loopback проверки не доказывают скорость VPS на существующем аккаунте.
Предыдущие реальные замеры до исправления HTTP 500: 1384/1697ms клиент,
609/931ms сервер. Разница около 0.77s не равна времени рендера.
Общее устранение задержек пока не подтверждено: нужны повторные замеры после
исправления HTTP 500 и ресурсы VPS в момент задержки. Эти CSS-изменения не
объявляются исправлением всех тормозов.

Новые сценарии: мобильный диалог, touch-target полей зарплаты и число запросов,
диалог 320×568 с увеличенными шрифтами и доступным закрытием.
Playwright baseline 54 → 57; Vitest 92 и Java 2907 остаются прежними.
Бюджеты frontend не повышаются. Выпуск через test/staging, без production.
