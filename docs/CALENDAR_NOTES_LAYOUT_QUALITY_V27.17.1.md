# DutyLog v27.17.1 — Calendar & Notes Quality Hotfix

## Причина релиза

Первая реальная проверка `v27.17.0` показала три независимых UX-дефекта:

1. на широком desktop viewport редактор заметок внутри узкой правой панели продолжал выбирать горизонтальную desktop-компоновку и выходил за пределы контейнера;
2. важная дата могла получить устаревшую дату формы и одновременно показывалась в all-day зоне и как фиолетовое timed reminder-событие поверх смены;
3. HTML-поле срока задачи ограничивало минуты шагом `5`, поэтому `17:41` считалось недопустимым значением.

## Контракт исправления

### Container-aware notes

`dayNotesModule` становится именованным inline-size container. Раскладка зависит от ширины самой панели:

- широкий standalone-контейнер: список и редактор могут стоять рядом;
- узкая боковая панель: список находится сверху, редактор — снизу;
- очень узкая панель: кнопки действий и full-screen action занимают безопасные строки.

Глобальный `@media` оставлен только как fallback для старых браузеров.

### Contextual important-date creation

При открытии панели выбранного дня `#impDate` сразу синхронизируется с `state.selected`. Создание из календаря больше не использует старое значение, оставшееся после предыдущего дня.

### All-day rail

Day mode получает явную зону «Весь день» с отдельным заголовком и компактными элементами. Туда попадают:

- важные даты;
- задачи без времени;
- заметки дня;
- смены без временных сегментов.

Напоминания выбираются по фактической дате `displayAt` / `remindAt`. `IMPORTANT_DAY` notification delivery не создаёт второе timed-событие, потому что сама важная дата уже представлена в all-day rail.

### Minute precision

`#taskEditDueTime` использует `step="60"`. Значения вроде `17:41`, `08:03` и `20:37` проходят native browser validation и сохраняются через существующий API.

## Совместимость

- схема БД не менялась;
- Flyway остаётся V36;
- API не менялся;
- Classic остаётся доступен;
- Month / Week / Day используют прежние authoritative stores;
- бизнес-логика overtime/FIFO, задач, смен и заметок не менялась.

## Регрессии

- существующий Playwright calendar scenario создаёт реальную важную дату и проверяет all-day rail;
- existing multiple-notes scenario запускается на desktop viewport и проверяет локальную container-компоновку;
- existing editor-modals scenario сохраняет `17:41`;
- Java frontend contracts защищают CSS/DOM/JS-инварианты.
